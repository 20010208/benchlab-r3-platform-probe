DEFECTS FOUND BY THESE TESTS AND FIXED BEFORE THIS RUN (history, for the auditor)
  1. Double claim: byte-identical concurrent STARTED commits (same run id and time) let a no-op push look like a win -> per-record 128-bit nonce.
  2. HALT writer crash on a truncated ledger with a stale anchor tag -> an occupied anchor slot is a lost CAS and HALT falls back to HALT.json.
  3. Hash/URL/name regexes ended in `$`, which accepts a trailing newline -> all anchored with \Z.
  4. HALT could be defeated by odd reason text (a newline in verifier output made the HALT record schema-invalid and the error was swallowed) -> reasons are sanitised and any chain-record failure falls back to HALT.json.
  5. Push classification treated every server-side `[remote rejected]` as a rule rejection, so race losers exited instead of re-deciding -> classified by meaning (rule texts vs non-fast-forward / fetch first / slot taken).
  6. The frozen-journal pairing and history-shape checks were added so that old attempt files and ledger<->journal SUCCESS binding are protected per wake without re-running history.
